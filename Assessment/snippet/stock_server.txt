Answer: 

Issue 1: PriceDetails.getAverage() divides by 0 (wrong math + Infinity/NaN)


getAverage() {
  return (this.open + this.close + this.high + this.low) / 0;
}

Division by 0 is invalid for “average”.
If all numbers are valid → result becomes Infinity (not NaN).
If any value is undefined → sum becomes NaN, so result is NaN.

Fix (divide by 4 + validate numbers)

getAverage() {
  const vals = [this.open, this.close, this.high, this.low];
  if (!vals.every(Number.isFinite)) {
    throw new Error('Invalid OHLC: all values must be finite numbers');
  }
  return (this.open + this.close + this.high + this.low) / 4;
}


Issue 2: Server creates PriceDetails with close = undefined (bad data → NaN/throws)
const details = new PriceDetails(100, undefined, 120, 90);

This guarantees broken calculations.
After adding validation, this will throw → your server will crash unless handled.

 keep possibility of invalid data, but catch and respond 400:
 
if (req.url === '/stock' && req.method === 'GET') {
  try {
    const details = new PriceDetails(100, undefined, 120, 90); // could be invalid
    const stockPrice = new StockPrice('AAPL', details);
    const stock = new Stock('AAPL', 'Apple Inc.', stockPrice);

    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify(stock.getSummary()));
  } catch (err) {
    res.writeHead(400, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ error: err.message }));
  }
}Using try...catch alone won’t fix this issue because JavaScript doesn’t throw errors for undefined arithmetic or division by zero—it returns NaN. 
The correct approach is to validate inputs and fail fast inside the domain logic, 
throwing errors when data is invalid. Then, try...catch should be used only at the API boundary to translate those errors into proper HTTP responses.


Issue 3: StockPrice.calculateChange() has no validation and can divide by zero
Bug:
calculateChange() {
  return ((this.priceDetails.close - this.priceDetails.open) / this.priceDetails.open) * 100;
}

Problems:
close undefined → NaN
open 0 → Infinity
non-numeric values → NaN

Fix
calculateChange() {
  const { open, close } = this.priceDetails;
  if (!Number.isFinite(open) || !Number.isFinite(close)) {
    throw new Error('Invalid open/close: must be finite numbers');
  }
  if (open === 0) {
    throw new Error('Open price cannot be 0 for percentage change');
  }
  return ((close - open) / open) * 100;
}


 Issue 4: Stock.getSummary() can return invalid values (NaN) silently
 Bug 
 
getSummary() {
  return {
    averagePrice: this.stockPrice.priceDetails.getAverage(),
    priceChange: this.stockPrice.calculateChange()
  };
}

“getSummary can return NaN silently because JavaScript allows invalid numeric operations like undefined arithmetic and division by zero without throwing errors.
 These NaN values propagate through calculations and are later serialized to null in JSON(JSON does not support NaN, Infinity, or -Infinity.), masking the issue. 
 The fix is to validate inputs and fail fast by throwing errors when data is invalid.”

 Fix: validating the inputs and using try and catch in server creation.

Issue 5: Tests asserting buggy behavior
bug: 
expect(summary.averagePrice).to.be.NaN;
expect(summary.priceChange).to.be.NaN;

Fix: Replace expect(NaN) with assertions on correct values and thrown errors.

For HTTP server route tests (mock req/res)
You will mock only HTTP layer objects, not business logic:
Mocked objects:

res.writeHead = spy/stub
res.end = spy/stub

Test cases:

GET /wrong returns 404
POST /stock returns 404
If you add try/catch for invalid data → invalid data returns 400

const request = require('supertest');
const { expect } = require('chai');
const { server } = require('../app'); // adjust path to your server file

describe('HTTP Server Tests', () => {

  it('GET /stock should return 200, JSON header, and summary response', async () => {
    const res = await request(server)
      .get('/stock')
      .expect(200);

    // Header validation (res.writeHead)
    expect(res.headers['content-type']).to.include('application/json');

    // Body validation (res.end)
    expect(res.body).to.be.an('object');
    expect(res.body).to.have.all.keys(
      'symbol',
      'companyName',
      'averagePrice',
      'priceChange'
    );

    // Fixed values
    expect(res.body.symbol).to.equal('AAPL');
    expect(res.body.companyName).to.equal('Apple Inc.');

    // Current buggy behavior (NaN -> null)

    expect(res.body.priceChange).to.equal(null);
  });

  it('Any other route or method should return 404 Not Found', async () => {

      .get('/invalid-route')
      .expect(404);

    expect(res.text).to.equal('Not Found');
